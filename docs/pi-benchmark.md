2026-11-07에 `scripts/check_blueprint.py`의 같은 바이트를 로컬과 `pi-slave1`에서
각각 한 번 실행했다. 양쪽 모두 exit 0, `ALL OK`이며 stdout의 SHA-256이 같았다.
유한 범위 전수 검사 결과의 재현 확인이고, 일반 정리의 Lean 증명은 아니다.

- 입력 파일 SHA-256: `4be3969b827f2549969e7c638e0808af4aa766ed64469308771938cf82c4a16e`
- stdout SHA-256: `3d2118652e6a9972278cdd30de3bec3f11dcad2a8254c4cda2b59f4112216836`
- 실행 방법(실행자 기록): 양쪽 모두 `python -I`로 임시 디렉터리의 동일한 소스 파일을 실행했다.
  `subprocess` 경과 시간과 자식 프로세스 `getrusage`를 측정했다. SSH 전송 시간은 제외했다.
- Pi 실행은 `nice -n 10`, 실행 시간 제한 180초이며 임시 파일은 종료 시 삭제했다.
  패키지 설치, Kubernetes 설정 변경, 상시 작업 등록은 하지 않았다.
- 단일 실행이며 Python 버전과 백그라운드 부하가 다르다. 하드웨어만의 성능 비교나
  반복 측정의 통계로 해석하지 않는다.

이번 조건에서 Pi 한 대는 로컬보다 약 6.15배 오래 걸렸다. 세 노드로 분산했을 때의
성능은 측정하지 않았다. 현재 크기의 검사를 빠르게 끝내는 데에는 로컬이 적합하고,
Pi는 개발 컴퓨터를 점유하지 않는 장시간 반례 탐색 후보로 둔다. 이후 검사 범위를 넓힐 때
독립 사례별 분할, 중복·누락 검사, 결과 수집을 도입한다. Lean/Mathlib 빌드는 기존 환경을 유지한다.
